# ArgoCD Setup: GitOps for assignment-portal on EKS

Installs ArgoCD, exposes the UI through an AWS LoadBalancer, and registers the `assignment-portal` Application so every push to `main` is deployed automatically.

> **Order matters.** Complete `README-monitoring.md` (at least the "Install kube-prometheus-stack" step) **before** applying the Application. The repo's `manifest_files/monitoring/` folder contains `ServiceMonitor` and `PrometheusRule` objects. Without the Prometheus Operator CRDs, ArgoCD rejects the entire sync.

---

## 1. Prerequisites

| Requirement | Check |
|---|---|
| EKS cluster running, `kubectl` configured | `kubectl get nodes` |
| Prometheus Operator CRDs installed | `kubectl get crd \| grep monitoring.coreos.com` |
| AWS Load Balancer Controller (the Ingress uses `ingressClassName: alb`) | `kubectl get pods -n kube-system \| grep load-balancer` |
| EBS CSI driver (Postgres PVC uses the `gp3-storage` StorageClass) | `kubectl get pods -n kube-system \| grep ebs-csi` |
| Worker node IAM role can pull from ECR (`AmazonEC2ContainerRegistryReadOnly`); the images are in ECR `us-east-1` | |
| `jq` (optional, for debugging) | `sudo apt install -y jq` |

## 2. Install ArgoCD

```bash
kubectl create namespace argocd
kubectl apply -n argocd -f https://raw.githubusercontent.com/argoproj/argo-cd/stable/manifests/install.yaml
```

Wait for all pods to be Running:

```bash
kubectl get pods -n argocd -w
```

---

## 3. Expose the ArgoCD UI via LoadBalancer

```bash
kubectl patch svc argocd-server -n argocd -p '{"spec": {"type": "LoadBalancer"}}'
kubectl get svc argocd-server -n argocd
```

`EXTERNAL-IP` is an AWS DNS name and may show `<pending>` for 1-2 minutes. Open:

```
https://<argocd-elb-dns>
```

The browser shows a **self-signed certificate warning**. This is expected; proceed past it.

Optional: restrict the UI to your IP.

```bash
kubectl patch svc argocd-server -n argocd \
  -p '{"spec":{"loadBalancerSourceRanges":["<YOUR_IP>/32"]}}'
```

## 5. Application definition

File in the repo: `argoCD/application.yaml`

```yaml
apiVersion: argoproj.io/v1alpha1
kind: Application
metadata:
  name: assignment-portal
  namespace: argocd

spec:
  project: default

  source:
    repoURL: https://github.com/YashwanthGowdaM/assignment-portal-k8s.git
    targetRevision: main
    path: manifest_files
    directory:
      recurse: true            # includes manifest_files/monitoring/

  destination:
    server: https://kubernetes.default.svc
    namespace: assignment-portal

  syncPolicy:
    automated:
      prune: true              # deletes cluster resources removed from Git
      selfHeal: true           # reverts manual kubectl edits
    syncOptions:
      - CreateNamespace=true
```

If the GitHub repo is **private**, add credentials first (**Settings → Repositories**, HTTPS with a personal access token), or:

```bash
argocd repo add https://github.com/YashwanthGowdaM/assignment-portal-k8s.git \
  --username YashwanthGowdaM --password <GITHUB_PAT>
```

## 9. How day-to-day work looks

1. Edit manifests in the repo.
2. `git commit` and `git push` to `main`.
3. ArgoCD polls about every 3 minutes (click **Refresh** to force it) and applies the change.

Do **not** use `kubectl apply` or `kubectl edit` on managed resources. `selfHeal` reverts them.

## 10. Troubleshooting

### Everything shows OutOfSync on first load, diff only shows `argocd.argoproj.io/tracking-id`
Expected. The resources were originally created with `kubectl apply`, so they lack ArgoCD's tracking annotation. The first successful sync adds it. No data changes.

### Sync fails: `failed to discover server resources for group version monitoring.coreos.com/v1`
The Prometheus Operator CRDs are not installed. Install `kube-prometheus-stack` (see `README-monitoring.md`), then retry:

```bash
kubectl patch application assignment-portal -n argocd --type merge -p '{"operation":null}'
kubectl annotate application assignment-portal -n argocd argocd.argoproj.io/refresh=hard --overwrite
```

ArgoCD does not retry a failed commit indefinitely, so a **stale error can remain** after the cause is fixed. A new `git push`, **Refresh → Hard Refresh**, or **Sync → Synchronize** clears it.

### Find what is blocking a sync

```bash
# Phase and message of the current operation
kubectl get application assignment-portal -n argocd \
  -o jsonpath='{.status.operationState.phase}{"\n"}{.status.operationState.message}{"\n"}'

# Resources that are not Synced
kubectl get application assignment-portal -n argocd -o json | \
  jq -r '.status.resources[] | select(.status!="Synced") | "\(.kind)/\(.name)  sync=\(.status)"'

# Application conditions and events
kubectl describe application assignment-portal -n argocd | tail -30
```

### Pods in `ImagePullBackOff`
The node IAM role lacks ECR pull permission. Attach `AmazonEC2ContainerRegistryReadOnly`. Images are in `us-east-1` while the cluster is in `us-east-2`; cross-region pulls work with that policy.

### HPA shows `did not receive metrics for targeted pods`
Install metrics-server and ensure each Deployment defines `resources.requests.cpu`:

```bash
kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
kubectl top pods -n assignment-portal
```

### LoadBalancer stuck on `<pending>`
The cluster cannot provision AWS load balancers. On EKS this normally works; on a self-managed cluster you need the AWS Cloud Controller Manager.

## 11. Safety recommendations

`prune: true` deletes anything ArgoCD manages that disappears from Git. Protect resources whose deletion would destroy data by adding this annotation to the **Namespace** and **StorageClass** manifests:

```yaml
metadata:
  annotations:
    argocd.argoproj.io/sync-options: Prune=false
```

Also:

- Keep secrets out of plain Git for anything beyond a demo (use Sealed Secrets, External Secrets, or SOPS).
- Restrict the ArgoCD LoadBalancer to your IP.
- The `monitoring` Helm release is **not** managed by ArgoCD. To make it declarative later, add a second ArgoCD Application pointing at the kube-prometheus-stack chart with values in Git.

## 12. Cleanup

Delete the app first so ArgoCD removes its resources (including the ALB created by the Ingress):

```bash
kubectl delete application assignment-portal -n argocd
kubectl delete namespace argocd
```

Remove the load balancers (ArgoCD, Grafana, Prometheus, Ingress ALB) **before** deleting the EKS cluster. Otherwise the ELBs and their security groups can be left behind, block VPC deletion, and keep billing.
